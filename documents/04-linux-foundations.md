# Linux Foundations — Filesystem, Shell, Packages, Services (CIS 141)

## The Filesystem Hierarchy (FHS) Tour

Linux puts everything under one root `/` — no drive letters. What lives where, and why:

- `/bin`, `/usr/bin` — essential and general user commands (`ls`, `cp`, `grep`). `/sbin`, `/usr/sbin` — system administration commands.
- `/etc` — host-specific **configuration** as text files. "How is this machine set up?" is answered in /etc.
- `/home` — users' personal directories (`/home/alex`). `/root` is the root user's separate home.
- `/var` — **variable** data that grows: `/var/log` (logs), `/var/lib` (state), spool and cache. A full disk is very often a swollen /var/log.
- `/tmp` — world-writable scratch, cleared on a schedule or at boot; never store anything precious there.
- `/dev` — device files: disks appear as files (`/dev/sda`, `/dev/nvme0n1`) so programs can treat hardware uniformly.
- `/proc` and `/sys` — **virtual** filesystems generated by the kernel: process information, kernel state, hardware knobs. They occupy no real disk space.
- `/boot` — kernel images and the bootloader configuration.
- `/lib`, `/usr/lib` — shared libraries programs link against.
- `/opt` — self-contained third-party software; `/srv` — data served by this machine; `/mnt`, `/media` — mount points for filesystems.
- `/usr` — the bulk of the installed system (programs, libraries, documentation); historically "Unix system resources," not "user."

FHS reasoning skill: an unknown path is classified by its parent. Something under /etc is configuration, under /var is state or logs, under /usr is installed software.

## The Shell and How to Read a One-Liner

The shell (usually **bash**) receives a line, expands it, and runs commands connected by operators. Reading a one-liner token by token:

- **Pipe `|`** — stdout of the left command becomes stdin of the right: `journalctl -u sshd | grep Failed` reads as "show the sshd log, then keep only lines containing Failed."
- **Redirection** — `>` writes stdout to a file (truncating), `>>` appends, `<` feeds a file as stdin, `2>` redirects stderr, `2>&1` sends stderr to the same place as stdout.
- **`&&` / `||` / `;`** — run the next command only if the previous succeeded / only if it failed / regardless. Exit status 0 means success; anything else is a failure code.
- **Variables and substitution** — `$VAR` expands a variable; `$(command)` expands to the command's output; quotes matter: double quotes allow expansion, single quotes are literal.
- **Globbing** — `*` and `?` are expanded by the shell into matching filenames *before* the command runs.

Anatomy example: `sudo systemctl restart sshd && systemctl is-active sshd` — "restart sshd with privilege; if (and only if) that succeeded, ask whether it is now active." Alex prefers one-liners himself; this is the grammar they are written in.

## Package Managers — apt and dnf

Distributions install software as **packages** tracked in repositories, with dependencies resolved automatically:

- **Debian family (Debian, Ubuntu, Pop!_OS):** `apt update` refreshes the package lists (it installs nothing), `apt upgrade` upgrades installed packages, `apt install <pkg>` / `apt remove <pkg>` manage software. The low-level tool underneath is `dpkg` (single .deb files, no dependency solving).
- **Red Hat family (RHEL, Fedora, Rocky):** `dnf install / remove / upgrade`, with `rpm` as the low-level tool.
- Concepts that transfer across both: repositories are trust decisions (a repo can install anything as root), `autoremove` cleans orphaned dependencies, and a package held/pinned stays put during upgrades.
- Never pipe a random internet script into root's shell to "install" something when the distribution packages it — the package manager is the auditable path.

## Service Management with systemd

**systemd** is the init system and service manager on nearly all modern distributions:

- A **unit** is a managed thing: `.service` (a daemon), `.timer` (scheduled run), `.socket`, `.mount`, `.target` (a grouping/sync point like `multi-user.target`).
- **systemctl verbs** to know cold: `start`, `stop`, `restart`, `reload` (re-read config without dropping the process, where supported), `status`, `enable` / `disable` (boot-time start — note `start` and `enable` are different questions), `mask` (forbid starting at all), `daemon-reload` (after editing unit files).
- **journalctl** reads the systemd journal — the central log: `journalctl -u sshd` (one unit), `-b` (this boot), `-f` (follow live), `--since`, `-p err` (priority filter). "**journalctl** is where you ask what a service said about itself."
- Runlevels are history: targets replaced them (`graphical.target` ≈ old runlevel 5).
